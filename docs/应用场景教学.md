# CCMake 典型应用场景教学

本文用一个最小的 C 程序演示 CCMake 的完整使用方式：

```text
配置（.ccm）
    ↓
构建脚本（.cmk）
    ↓
Configure：执行脚本、生成构建计划
    ↓
Build：Scheduler 调度目标，Executor 执行编译命令
```

示例位于 [examples/hello](../examples/hello)。

## 1. 关于可执行文件名字

构建产物统一为 `ccmake`（Windows 为 `ccmake.exe`），与项目名 CCMake 一致。

CMake 也自带一个 `ccmake`（curses 配置界面）。如果两者都在 PATH 中，后者的同名命令可能遮蔽本项目。处理原则：

- 安装时把 CCMake 的 `ccmake` 放在独立目录，或优先使用完整路径；
- 不为了规避重名而改掉项目自己的二进制名；
- 文档、脚本、示例统一使用 `ccmake`。

```bat
:: Windows：优先用完整路径，避免 PATH 中 CMake 的 ccmake 抢先
D:\tools\ccmake\ccmake.exe -c project.ccm -f build.cmk
```

```bash
# Linux/macOS：确认实际命中的是哪个 ccmake
command -v ccmake
```

## 2. 场景

编译一个 C 程序：

```text
examples/hello/
  project.ccm      配置：编译器、编译选项
  build.cmk        构建脚本：目标、输入、输出、动作
  src/main.c       源码
```

### project.ccm

```text
"project": "hello";
"toolchain": {
    "cc": "gcc";
    "cflags": ["-O2", "-Wall"];
};
```

要点：

- `.ccm` 对象成员用分号结尾；
- 数组使用 `[]`；
- `@{toolchain.cc}` 在 `.cmk` 中读取嵌套配置；
- `@{toolchain.cflags}` 是 `list<string>`。

### build.cmk

```c
@include "project.ccm";

target main() {
    list<target_ref> depends_on = {hello};
}

target hello() {
    list<string> inputs = {"src/main.c"};
    list<string> outputs = {"build/hello.exe"};
    list<action> actions = {
        mkdir("build"),
        command(
            @{toolchain.cc},
            @{toolchain.cflags} + {"src/main.c", "-o", "build/hello.exe"}
        )
    };
}
```

要点：

- `main` 是聚合目标，只依赖 `hello`；
- `hello` 才真正执行编译；
- `inputs`、`outputs` 用于增量缓存签名；
- `actions` 按顺序执行：
  1. `mkdir("build")`；
  2. 调用 gcc 编译。
- `command` 的 argv 直接传给进程，不经过 shell；
- 每个语句以分号结尾。

### src/main.c

```c
#include <stdio.h>

int main(void)
{
    puts("hello from CCMake");
    return 0;
}
```

## 3. 构建

进入示例目录：

```bat
cd examples\hello
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk
```

Linux 下二进制路径不同：

```bash
cd examples/hello
../../out/linux_amd64_bin/ccmake -c project.ccm -f build.cmk
```

预期：

```text
build/hello.exe
```

运行：

```bat
build\hello.exe
```

输出：

```text
hello from CCMake
```

## 4. 只构建指定目标

```bat
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk -t hello
```

- 省略 `-t` 时默认是 `main`；
- 只构建该目标的依赖闭包；
- 不自动构建未被选中的孤立目标。

列出目标：

```bat
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk --list-targets
```

## 5. 并发构建

```bat
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk -j 4
```

- `-j` 控制 READY 批次并发上限；
- `-j 0` 自动检测 CPU 核心数；
- 每个目标内部的 actions 仍按顺序执行；
- 目标之间由依赖图决定先后。

## 6. 增量构建与缓存

第一次构建后会在当前目录生成：

```text
.ccmake-cache
```

再次执行同一命令：

```bat
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk
```

`hello` 目标会命中缓存并标记为 `SKIPPED`，不会重新调用 gcc。

修改 `src/main.c` 后再次构建会失效并重新编译。

强制重建：

```bat
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk -B
```

缓存签名包含：

- 输入文件内容；
- 输出文件内容；
- 动作 program；
- argv；
- env；
- cwd；
- 目标身份。

注意：依赖目标的输出不会自动加入下游签名。若下游目标依赖上游产物，应把该产物显式写入下游的 `inputs`。

## 7. 失败与继续

```bat
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk -k
```

- 默认 fail-fast：失败后不再启动后续批次；
- `-k/--keep-going`：继续执行不依赖失败目标的独立任务；
- 依赖失败的目标进入 `BLOCKED`；
- 当前 fail-fast 是批次粒度，已启动批次会允许完成。

## 8. 目录与工作目录

CMK 中的相对路径按当前进程工作目录解析。

推荐：

```bat
cd examples\hello
..\..\out\windows_amd64_bin\ccmake.exe -c project.ccm -f build.cmk
```

`-C <目录>` 设置 CCMake 的工作目录字段，供配置与文件定位使用；外部命令默认继承启动 `ccmake` 时的进程 cwd，除非 `command` 动作显式提供 cwd 参数。路径关系复杂时，优先显式 `cd` 到项目目录，或在动作中写明确的 cwd。

## 9. 常见问题

### gcc 找不到

确认 `gcc` 在 PATH 中：

```bat
gcc --version
```

或把 `project.ccm` 的 `toolchain.cc` 改成完整路径。

### 输出文件不存在

检查：

- `outputs` 与实际命令输出是否一致；
- Windows 下 gcc 可能生成 `.exe` 后缀；
- `command` 的 `-o` 参数是否与 `outputs` 一致。

### 缓存没有命中

检查：

- 输出文件是否存在；
- 输入文件是否变化；
- 是否使用了 `-B`；
- 目标是否有 `outputs`。

### 日志顺序

并发目标由多个线程执行，但进程输出先写入 Executor 结果，再由 Scheduler 按稳定顺序输出。日志不会按线程完成时间乱序。

## 10. 模块边界

```text
CMK Program
  ├─ Parser / Semantic / Runtime
  ├─ Lowering → CMKPlan
  ├─ Scheduler
  │    ├─ CacheOps（可选）
  │    └─ ExecutorOps
  ├─ Executor
  │    └─ Process
  └─ Cache
```
