# 全局变量树

全局变量树是 CCMake 内部保存 `.ccm` 配置结果的独立模块。解析器只通过路径写入和查询，树负责节点管理、键查找、覆盖与删除。

## 1. 模块边界

| 项 | 内容 |
|---|---|
| 依赖 | CrystalStd 的 `ccalloc`、`cc_dyn`、`cc_rbt` |
| 上层职责 | 解析器负责 `.ccm` 文本与写入顺序；VFS 负责文件发现；诊断由调用方输出 |
| 对外形态 | 不透明 `CCVarTree` 句柄 + 路径 API + `CCVarValue` 查询结果 |
| 内部形态 | 连续节点数组、对象成员红黑树、数组顺序表 |

树模块通过 `CCVarResult` 返回执行结果，由解析器结合 `.ccm` 文件与行号输出诊断。

## 2. 节点模型

```c
typedef struct cc_var_node {
    char     *name;          /* 对象成员键；数组元素与根为 NULL */
    CCUINT32  name_len;
    CCVarType type;

    CCUINT32  parent;        /* 层级父节点 */
    CCUINT32  children_root; /* 对象：子红黑树根 */

    CCUINT32  rbt_parent;    /* 红黑树链接 */
    CCUINT32  rbt_left;
    CCUINT32  rbt_right;
    CCBOOL    is_red;

    CCDyn     elements;      /* 数组：CCUINT32[]，按位置排列 */

    union {
        CCBOOL   boolean;
        CCINT64  integer;
        double   floating;
        struct {
            char    *data;
            CCUINT32 len;
        } string;
    } value;
} CCVarNode;
```

- 全部节点连续存放在 `CCDyn nodes` 中，节点之间使用 `CCUINT32` 下标互相引用；
- 根节点下标为 0，类型为 `OBJECT`，名字为空；
- 对象成员使用嵌套红黑树，键为成员名；
- 数组元素使用 `CCDyn` 顺序表，保留源文件中的元素顺序；
- 节点属性包含键、类型、值、父节点和子索引；文件、时间、挂载等元数据由其他模块管理。

## 3. 键名与路径

### 3.1 键名

```text
key := [A-Za-z_][A-Za-z0-9_]*
```

- ASCII；
- 首字符为字母或 `_`；
- 后续字符为字母、数字或 `_`；
- 大小写敏感；
- 空键、点号、方括号、连字符及其他字符均非法。

### 3.2 路径

```text
path := key ( "." key | "[" index "]" )*
```

示例：

```text
toolchain.c_compiler
defines[0]
targets[2].sources[1]
```

根对象用空字符串 `""` 表示。`ccvar_key_valid` 按键长校验键名，解析器在写入前调用。

## 4. 接口

```c
CCVarTree *ccvar_create(void);
void ccvar_destroy(CCVarTree *tree);
void ccvar_clear(CCVarTree *tree);

CCVarResult ccvar_set(
    CCVarTree *tree, const char *path,
    CCVarType type, const void *data,
    CCUINT32 len, CCVarWriteMode mode
);
CCVarResult ccvar_array_push(
    CCVarTree *tree, const char *array_path,
    CCVarType type, const void *data,
    CCUINT32 len, CCUINT32 *out_index
);

CCVarResult ccvar_get(const CCVarTree *tree, const char *path, CCVarValue *out);
CCVarType ccvar_type(const CCVarTree *tree, const char *path);
CCUINT32 ccvar_child_count(const CCVarTree *tree, const char *object_path);
CCINT32 ccvar_foreach_child(
    const CCVarTree *tree, const char *object_path,
    CCVarChildVisit cbk, void *user
);
CCUINT32 ccvar_array_size(const CCVarTree *tree, const char *array_path);
CCINT32 ccvar_foreach_element(
    const CCVarTree *tree, const char *array_path,
    CCVarElementVisit cbk, void *user
);

CCVarResult ccvar_remove(CCVarTree *tree, const char *path);
```

`ccvar_set` 与 `ccvar_array_push` 通过类型枚举与 `data` 指针统一接收所有值：

| `type` | `data` | `len` | `mode` |
|---|---|---|---|
| `CC_VAR_STRING` | 字节序列指针 | 字节数 | 忽略 |
| `CC_VAR_INT` | `CCINT64 *` | 忽略 | 忽略 |
| `CC_VAR_FLOAT` | `double *` | 忽略 | 忽略 |
| `CC_VAR_BOOL` | `CCBOOL *` | 忽略 | 忽略 |
| `CC_VAR_OBJECT` | `NULL` | 忽略 | `MERGE` / `REPLACE` |
| `CC_VAR_ARRAY` | `NULL` | 忽略 | 忽略 |

`ccvar_set` 负责完整写入（含旧值清理与对象合并）；`ccvar_array_push` 负责向已有数组追加元素，`out_index` 返回新元素位置。

查询返回值使用 `CCVarValue`：

```c
typedef struct cc_var_value {
    CCVarType type;
    union {
        CCBOOL   boolean;
        CCINT64  integer;
        double   floating;
        struct {
            const char *data;
            CCUINT32    len;
        } string;
    } as;
} CCVarValue;
```

字符串 `data` 指向树内存储，在对应节点被覆盖、删除或整树清理前有效。

## 5. 写入与覆盖

### 5.1 标量与数组

| 新值 | 目标已有 | 行为 |
|---|---|---|
| 字符串 / 整数 / 浮点 / 布尔 | 任意 | 删除旧值或旧子树，写入新标量 |
| 数组 | 任意 | 删除旧值或旧子树，写入空数组，再按顺序追加 |
| 对象，`CC_VAR_WRITE_REPLACE` | 任意 | 删除旧值或旧子树，写入空对象 |
| 对象，`CC_VAR_WRITE_MERGE` | 对象 | 保留既有成员，返回原对象，由后续成员写入覆盖 |
| 对象，`CC_VAR_WRITE_MERGE` | 非对象 / 不存在 | 删除旧值或新建空对象 |

写入 API 内部完成路径解析、同名键查找、旧值清理与新值安装。调用方直接写入目标路径。

### 5.2 对象浅合并

`CC_VAR_WRITE_MERGE` 只保留目标对象的既有成员；成员值整体替换。解析器对顶层字段的对象使用 `MERGE`，对对象内部的对象成员使用 `REPLACE`，由此得到规范要求的浅合并：

```text
base:  "a": { "x": 1; "y": 2; "n": { "p": 3; }; };
later: "a": { "x": 9; "n": { "q": 4; }; };

结果:
  a.x = 9
  a.y = 2
  a.n = { q: 4 }
```

### 5.3 数组

数组节点持有顺序表。`ccvar_array_push` 追加元素并按需返回新元素下标；对象或数组元素返回可继续写入的节点位置。数组赋值整体替换旧数组。

## 6. 查询与遍历

- `ccvar_get` 按路径返回类型与值；对象和数组返回类型，内容通过子节点遍历或数组索引访问；
- `ccvar_child_count` / `ccvar_foreach_child` 按红黑树中序遍历对象成员，键顺序确定；
- `ccvar_array_size` / `ccvar_foreach_element` 按位置遍历数组；
- 查询以路径和值为接口；节点下标属于树内部实现，外部只使用路径和值。

## 7. 删除

删除按路径定位子树：

1. 以先序收集子树节点路径；
2. 反转列表，从叶子到根逐个删除；
3. 对象成员通过 `cc_rbt_core_remove` 摘除，红黑树后继拷入时转移节点自有数据（键、值、子索引、数组顺序表）；
4. 通过 swap-remove 将末尾节点搬入被删槽位，修正红黑树父/子链接、父对象的 `children_root`、数组中的元素下标以及所有子节点的层级父节点；
5. 节点数组保持紧凑，删除节点的键与值立即释放。

删除过程使用路径列表定位待删节点；节点下标属于树内部实现。

## 8. 复杂度

设对象同层键数为 d、路径长度为 L、子树节点数为 s：

| 操作 | 复杂度 |
|---|---|
| 对象成员查找 | O(log d · L) |
| 对象成员插入 | O(log d · L) |
| 数组追加 / 索引 | O(1) |
| 路径查询 | O(深度 × log d · L) |
| 删除对象成员 | O(子树 + 红黑树与搬移修正) |
| 子节点遍历 | O(d) |
| 清空 / 销毁 | O(节点数) |

## 9. 全局单例

```c
CCBOOL     ccvar_global_init(void);
CCVarTree *ccvar_global(void);
void       ccvar_global_deinit(void);
```

`parse_ccm` 在第二阶段前初始化并清空全局树，解析成功后保留；`main` 在退出路径销毁。

## 10. 边界

- 树处理键值数据与路径寻址；
- `.ccm` 文本解析由内容解析模块完成，内建函数由内建函数模块求值，文件访问由 VFS 完成；
- 解析顺序由解析器按文件与语句顺序决定；
- 所有访问以路径或遍历回调完成；
- 键名与路径段遵循第 3 节规则，非法输入返回 `CC_VAR_ERR_PARAM`。
