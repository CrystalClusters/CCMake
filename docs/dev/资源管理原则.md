# 资源管理原则

## 内存

- 所有堆分配经 `ccalloc` / `ccfree`；
- 模块拥有自己创建的 AST、语义记录、字符串和列表；
- 值复制采用深复制，动作中的 `CMKList` 由动作值拥有；
- 函数返回的 `CMKValue` 由调用方清理；
- 失败路径释放已分配资源，不发布半成品对象。

## 执行限制

`CMKExecutionPolicy` 的字段全部默认 0：

| 字段 | 含义 |
|---|---|
| `max_steps` | Configure 最大执行步数 |
| `max_recursion_depth` | 函数调用深度 |
| `max_configure_time_ms` | Configure CPU 时间 |
| `max_find_depth` | `find_files` 目录深度 |
| `max_processes` | 并发进程上限 |
| `max_output_capture` | 单进程输出捕获上限 |

0 表示不设置上限，由实际内存、地址空间和宿主限制约束。

## 进程

- `command` 动作通过 `CMKProcess` 启动；
- 进程输出写入执行结果，由 `run` 输出；
- 输出捕获失败、信号终止、非零退出码均视为动作失败；
- 进程工作目录由动作 `cwd` 指定；未指定时继承 `ccmake` 进程 cwd。

## 文件动作

- `mkdir` 逐级创建目录；
- `copy` 复制文件内容；
- `move` 优先重命名，跨设备时复制后删除源；
- `remove` 删除文件或空目录；
- 文件动作失败使当前 `run` 停止并返回错误。

## 脚本资源

- `run` 只在调用时执行动作，动作列表本身不拥有进程资源；
- 脚本直接执行动作，不持有构建图或缓存资源；
- 脚本通过 `file_exists` / `file_mtime` / `file_newer` 自行决定是否重建。
