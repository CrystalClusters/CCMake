# 代码风格指南

本文记录 CCMake 现行的 C 代码组织、缩进、多行调用、资源生命周期、命名与注释规范。新增代码按本文执行，修改代码时同步整理所在函数的相邻风格。

## 1. 文件与编码

- 源文件使用 UTF-8 编码，构建参数统一带 `-fexec-charset=GBK`。
- 使用 4 个空格缩进，不使用制表符。
- 使用 LF 换行；仓库检出后的 CRLF 转换由 Git 配置处理。
- 文件头保留现有注释模板：

```c
/*
 * @Author: ...
 * @Date: 2026-11
 * @LastEditors: ...
 * @LastEditTime: 2026-11
 * @Description: ...
 * Copyright (c) 2026 by lizaterop@gmail.com, All Rights Reserved.
 */
```

- 公共声明放在对应模块头文件；实现文件优先包含自己的模块头。
- include 顺序：

```c
#include "本模块头文件.h"
#include "其他项目内部头文件.h"

#include <CrystalStd 公共头>
#include <C 标准库头>
```

项目内部头用双引号，CrystalStd 与标准库头用尖括号；三组之间空一行。

## 2. 缩进与括号

- 函数、`if`、`for`、`while`、`switch`、`struct`、`enum` 的左花括号独占一行。
- `else` / `else if` 与上一个右花括号同行之后换行：

```c
if (condition)
{
    ...
}
else
{
    ...
}
```

- 单条简单语句可以省略花括号：

```c
if (!tree)
    return CC_VAR_ERR_PARAM;

for (CCUINT32 i = 0; i < count; i++)
    ccalloc(items[i], 0, NULL);
```

- 语句跨行、包含声明、包含注释或多条语句时必须使用花括号。
- `switch` 的 `case` 与 `switch` 的右花括号同列，不额外缩进：

```c
switch (p->tok.type)
{
case CCM_TOK_STRING:
    ...
    break;

default:
    return ccm_parse_failf(...);
}
```

- `case` 分支内部使用 4 空格缩进。
- 空结构体、空函数体写成：

```c
{
}
```

不写成 `{}` 单行。

## 3. 函数定义与声明

- 返回类型、函数名、左括号在同一行。
- 参数超过一行时，每个参数一行；右括号独占一行，位于第 0 列。
- 函数体左花括号另起一行。

```c
static CCBOOL find_scan_dir(
    CCMFindScan *scan,
    const char *vpath
)
{
    ...
}
```

- 无参数函数使用 `(void)`。
- 函数声明与定义使用相同参数排列。
- 函数原型放头文件；只在当前文件使用的辅助函数加 `static`。
- 函数长度以单一职责为准；状态、路径构造、资源清理分别拆成辅助函数，不把大量细节塞进一个循环。

## 4. 声明、指针与表达式

- C99 混合声明可用，变量尽量在第一次使用处声明。
- 指针星号跟随变量：

```c
char *path;
const CCVarNode *node;
CCVarTree *tree;
```

- 类型转换写成：

```c
(CCVarNode *)ptr
(const char *)data
(CCUINT32)sizeof(CCVarNode)
```

- `sizeof` 使用括号：`sizeof(CCVarNode)`、`sizeof(*tree)`。
- 布尔值使用 `CCTRUE` / `CCFALSE`。
- 整数宽度使用 CrystalStd 类型：`CCUINT32`、`CCINT32`、`CCUINT64`、`CCINT64`。
- 赋值语句需要换行时，先断在 `=` 之后，续行相对语句缩进 4 空格：

```c
CCUINT32 count =
    ctx->order.size / (CCUINT32)sizeof(CCUINT32);
```

- 右侧仍然过长时，再在运算符后断行，并保持同一层级缩进：

```c
CCUINT32 count =
    ctx->order.size /
    (CCUINT32)sizeof(CCUINT32);
```

- 不写成“第一行先放一部分右侧表达式，第二行再对齐剩余部分”的混合形式。
- 其他表达式换行同样用缩进体现层级，不在同一层里一部分换行、一部分不换行。
- 不建议刻意压到很短的行；单行建议不超过约 120 列。长字符串、格式串、宏和文档链接不强制拆行。

## 5. 多行函数调用

多行调用统一采用以下形式。

### 5.1 普通语句 / 赋值 / 返回

函数名后立即换行，实参相对语句缩进 4 空格，右括号回到语句缩进：

```c
    CCVarNode *y = (CCVarNode *)cc_rbt_core_remove(
        &var_rbt_ops, root, (CCUINTPTR)key
    );
```

```c
    r = var_attach(
        tree, (CCVarPathSeg *)segs.array, count, type,
        copy, string_len, integer, floating, boolean
    );
```

```c
    return cc_rbt_core_inorder_tranverse(
        &var_rbt_ops,
        var_node_at(mutable_tree, n->children_root),
        &ctx, var_child_visit
    );
```

### 5.2 控制流中的多行调用

`if` / `while` 中的调用，实参相对语句缩进 8 空格，调用右括号缩进 4 空格并接比较，外层条件右括号回到语句缩进：

```c
    if (cc_dyn_core_push(
            &tree->nodes,
            (CCUINT32)sizeof(CCVarNode),
            (CCINT32)sizeof(CCVarNode),
            &node
        ) != 0
    )
    {
        ...
    }
```

```c
    if (!parser_set_value(
            p, path, CC_VAR_STRING,
            p->tok.text, p->tok.len,
            CC_VAR_WRITE_REPLACE, "写入字符串"
        )
    )
        return CCFALSE;
```

- 多行调用不在最后一行实参后直接写 `);` 或 `) != 0)`。
- 短参数可以合并到一行，按语义分组。
- 函数声明、调用、控制条件都遵循同一闭合括号规则。

## 6. `goto` 与失败标签

CCMake 采用“报错即退出、失败即回滚”的单出口风格，标签放在函数末尾。

### 6.1 成功/失败标签

```c
    if (!parser_advance(p))
        goto Failed;
    if (!parser_parse_value(p, child, mode, depth))
        goto Failed;

    ccalloc(child, 0, NULL);
    return CCTRUE;

Failed:
    ccalloc(child, 0, NULL);
    return CCFALSE;
```

- 成功路径正常返回，不用 `goto Done` 再判断成功标志。
- 失败标签命名表达阶段：`FailedtoParse`、`FailedtoInitGlobal`、`FailedPaths`、`FailedJoined`。
- 具体失败标签在前，通用失败标签在后，利用 fallthrough 逐级释放：

```c
FailedJoined:
    ccalloc(joined, 0, NULL);
FailedPaths:
    ccalloc(cr, 0, NULL);
    ccalloc(cv, 0, NULL);
    return CCFALSE;
```

### 6.2 释放顺序

- 同一函数创建 A → B → C，失败时按 C → B → A 释放。
- 标签只释放该阶段已经确定创建成功的资源。
- 确定非空的指针直接释放，不在清理标签里加无意义判空。
- 可选资源、集合容器、外部输入指针按各自契约判断。
- 不依赖 `ccalloc(NULL, 0, NULL)` 的空操作行为；空指针释放必须显式判断。

### 6.3 所有权

每个资源在任意时刻必须有且只有一个明确的所有者；所有权转移必须显式发生；释放责任归最终所有者；借用者不得释放或延长资源生命周期。

- 创建者不一定永远是最终释放者；
- 接收者可以通过明确的转移取得所有权；
- 借用者可以使用资源，但不能负责它的生命周期；
- 容器成功接收元素后，容器所有者负责释放元素。

| 场景 | 规则 |
|---|---|
| 构造函数返回对象 | 调用方持有，调用对应 destructor |
| 栈上下文 `init` / `clear` | 同一作用域成对调用 |
| 局部路径 / 临时字符串 | 创建函数内释放，或明确转移给接收者 |
| 集合 `CCDyn *out` 追加 | 成功追加后集合持有元素，集合所有者释放 |
| `ccm_append_file` | 复制 `real_path`，调用方释放原路径 |
| `ccm_scan_includes` | 成功追加的边持有 `literal`，`out_includes` 所有者释放 |
| 查询返回字符串 | 借用树内存储，树修改后失效 |
| `ccm_builtin_eval` / `ccm_find_eval` 的 `out` | 调用方用 `ccalloc(*out, 0, NULL)` 释放 |
| `ccvar_set` 的 `data` | 只读，树内部复制，不接管调用方指针 |

创建函数与释放函数成对出现：

- `init_global_var` / `clear_global_var`
- `ccvar_global_init` / `ccvar_global_deinit`
- `ccvar_create` / `ccvar_destroy`
- `ccm_context_init` / `ccm_context_clear`
- `ccfiles_create` / `ccfiles_destroy`

### 6.4 `main` 的标签

成功与动作结束走 `Done`；失败标签逐级回落：

```c
Done:
    clear_global_var();
    ccvar_global_deinit();
    return 0;

FailedtoParseConfig:
FailedtoInitGlobal:
FailedtoParseCmd:
    clear_global_var();
    ccvar_global_deinit();
    return 1;
```

一次运行只执行一条清理路径，不依赖重复清理。

## 7. 命名

| 类别 | 规则 | 示例 |
|---|---|---|
| 公共类型 | `CC` / `CCM` / `CCVar` 前缀 + PascalCase | `CCVarTree`, `CCMakeCCMFile` |
| 内部类型 | 模块前缀 + 小写 `_struct` 标签 | `ccm_find_scan`, `cc_var_node` |
| 枚举值 | 全大写 + 模块前缀 | `CC_VAR_STRING`, `CCM_TOK_STRING` |
| 宏 | 全大写 + 模块前缀 | `CCM_MAX_...`, `CC_VAR_TAG` |
| 公共函数 | 模块前缀 + 小写下划线 | `ccvar_set`, `ccm_context_clear` |
| 静态辅助函数 | 模块内前缀 + 小写下划线 | `parser_parse_value`, `find_scan_entry`, `var_rbt_find` |
| 普通变量 | 小写下划线 | `string_len`, `include_count` |
| 文件级静态状态 | `g_` 前缀 | `g_index`, `g_var_tree` |
| 回调类型 | `CC...Visit` / `...Callback` | `CCVarChildVisit` |

命名表达“是什么”而不是“怎么做”。避免无意义的 `tmp`、`data2`、`foo`。

## 8. 注释

### 8.1 注释种类

- 接口文档注释使用 `/** ... */`，一般只用于描述公开接口的功能、参数、返回值或所有权：

```c
/**
 * 按路径写入一个值。
 * data 只读，树内部复制，不接管调用方指针。
 */
CCVarResult ccvar_set(...);
```

- 普通注释使用 `//`，不要用 `/* ... */` 代替普通行注释。
- `/* ... */` 只用于文件头、内部特殊说明和大段分区标记，例如：

```c
/* ============================================================================
 * 删除：路径收集、叶子摘除、swap-remove
 * ========================================================================== */
```

- 文件头保留现有块注释模板；它不是普通注释。

### 8.2 空格与对齐

- 独占一行的 `//` 注释，在 `//` 后加一个空格：

```c
// 一般注释
```

- 行尾注释与代码之间至少一个空格，`//` 后同样留一个空格：

```c
char *work_dir;   // -C / --directory
```

- 结构体字段的尾注释可以按列对齐，便于扫描：

```c
struct ccmake_global_var_struct {
    char *work_dir;          // -C / --directory
    char *output_dir;        // -o / --output
    CCUINT32 jobs;           // -j / --jobs
    CC_CMD_PARSE_STAT stat;  // 状态枚举
};
```

- 注释解释约束、所有权、失败后果；不重复代码字面含义。
- 资源转移、借用、释放责任必须写在接口或调用点附近。
- 中文标点与中文注释保持一致；代码标识符使用英文。

## 9. 头文件

- 使用 include guard，宏名与文件名一致：文件名去掉 `.h`、转大写，加 `_INCLUDE_` 前缀和 `_H_` 后缀。例如 `ccvar.h`：

```c
#ifndef _INCLUDE_CCVAR_H_
#define _INCLUDE_CCVAR_H_
...
#endif
```

`_H_` 是头文件后缀标记；文件名中的 `.h` 不进入宏名的文件名部分。

- 头文件只放声明、类型、宏；不放可执行实现。
- 内部头文件命名以模块为单位：`ccm_internal.h`、`ccvar_internal.h`、`ccm_scan_util.h`。
- 公共 API 头文件不包含实现细节结构。
- 修改结构体字段时同步更新初始化、清理、文档与测试。

## 10. 数据结构与内存

- 使用 `ccalloc`，不直接使用 `malloc` / `free`。
- 动态数组使用 `CCDyn`，通过 `cc_dyn_core_push` / `pop` / `seek` / `set` 操作。
- 元素之间保存下标，不跨扩容保存元素指针。
- 对象成员使用 `cc_rbt_core` 红黑树；数组使用顺序表。
- 字符串长度使用 `CCUINT32` 时，源头必须检查不超过 `UINT32_MAX`。
- 所有公开写入接口在分配前检查整数溢出、容量上限和表示范围；不设置普通资源的固定硬上限。
- 不在树节点中保存文件、时间、挂载等外部元数据。

## 11. 错误处理

- 失败返回 `CCFALSE` 或明确的 `CCVarResult`。
- 诊断格式：

```text
配置文件解析失败：<文件>:<行>: <说明>
配置文件定位失败：<文件>:<行>: <说明>
```

- 解析采用首错终止。
- 不吞错误；内层失败向上返回，由拥有上下文的层统一清理。
- 资源不足、格式错误、预算超限分别给出可理解的说明。
- 不使用断言代替用户输入校验。

## 12. 测试代码

- 测试套件按 `CMD`、`CCM`、`PARSE`、`VARS` 分组。
- 用例 ID 使用 `XXX-NNN`，中文标题说明行为。
- 断言使用 `CC_CHECK`、`CC_CHECK_EQ_I64`、`CC_CHECK_EQ_STR` 等统一宏。
- 测试 fixture 放在 `tests/data/`，不参与测试程序编译。
- 每个用例结束恢复全局状态，避免用例间互相污染。
- 失败路径测试要覆盖资源回滚与后续复用。

## 13. 文档

- 开发文档放在 `docs/dev/`，用户文档放在 `docs/`。
- 标题层级从 `#` 开始，代码块标注语言。
- 技术选型写正向结构与约束，不写过程性对比。
- 新增模块在 [开发手册](开发手册.md) 挂链接。
- 算法说明包含：输入、数据结构、步骤、复杂度、资源所有权。

## 14. 格式检查清单

提交前自查：

- 4 空格缩进，无制表符，无行尾空格；
- 花括号换行风格一致；
- 多行调用按第 5 节闭合；
- 失败标签按资源阶段倒序释放；
- 确定非空资源不在清理标签中判空；
- 不依赖 `ccalloc(NULL, 0, NULL)` 兜底；
- 新增创建接口有对应释放接口；
- 头文件、文档、测试同步更新；
- Debug 与 Release 均通过，Release 无 `-Werror` 告警。
