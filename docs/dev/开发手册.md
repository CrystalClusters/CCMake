## 全局变量

命令行解析后，参数值填充到 `ccmake_global_var` 结构体中。访问方式为 `ccmake_global_var.xxx`。

```c
typedef enum {
    CC_CMD_FLAG_ACTION_DONE,  // 已执行动作类参数，后续无需继续
    CC_CMD_FLAG_NEED_BUILD    // 需要执行构建
} CC_CMD_PARSE_STAT;

// 需要配置的动作类参数：解析阶段只记录，由后续流程执行
typedef enum {
    CC_CMD_ACTION_NONE,
    CC_CMD_ACTION_DUMP_CONFIG
} CC_CMD_ACTION;

// -D / --define 的单个键值对
typedef struct ccmake_define_struct {
    char *key;    // 键（ccalloc 分配）
    char *value;  // 值（ccalloc 分配）
} CCMakeDefine;

struct ccmake_global_var_struct {
    char *self_path;
    char *ccm_path;          // -c / --config
    char *cmk_path;          // -f / --file
    char *work_dir;          // -C / --directory
    char *output_dir;        // -o / --output
    int   jobs;              // -j / --jobs
    CC_CMD_PARSE_STAT stat;  // 状态枚举，告知后续流程走哪个分支
    CCBOOL  verbose;         // -v / --verbose
    CCBOOL  dry_run;         // -n / --dry-run
    CCBOOL  always_build;    // -B / --always-build
    CCBOOL  keep_going;      // -k / --keep-going
    CCDyn   defines;         // -D / --define：CCMakeDefine 动态数组
    CC_CMD_ACTION action;    // 需要配置的动作类参数，由后续流程执行
};
```

**`stat` 字段说明**：

| 枚举值 | 含义 |
|---|---|
| `CC_CMD_FLAG_ACTION_DONE` | 已执行动作类参数（如 `-V`、`-h`），`main` 应直接 `return 0`，不再执行构建 |
| `CC_CMD_FLAG_NEED_BUILD` | 需要继续执行构建操作（指定了 `-f` 且无动作类参数），`main` 应继续构建流程 |

**动作类参数的处理**：

| 参数 | 解析阶段行为 |
|---|---|
| `-h` / `-V` | 立即执行，`stat` 置 `CC_CMD_FLAG_ACTION_DONE`，`parse_cmd` 直接返回 `true` |
| `--dump-config` | 只写 `action`，解析继续以收集配置；`parse_cmd` 在存在动作请求时跳过构建必填项校验 |

**平台与架构名称**：

`ccmake_header.h` 中的 `CCMAKE_PLATFORM_NAME` / `CCMAKE_ARCH_NAME` 来自平台宏与构建脚本传入的 `CC_ARCH_*`，供 `--version` 输出使用。

**`-D` 键值对的存储**：

`-D` 解析出的键值对用 CrystalStd 的动态数组 `CCDyn` 保存，元素为 `CCMakeDefine`（键、值各一块 `ccalloc` 内存）：

- 压入时 `align` 与 `size` 都取 `sizeof(CCMakeDefine)`，元素个数为 `defines.size / sizeof(CCMakeDefine)`。
- 重复的键保留首次插入的位置，值以后出现者为准。
- 遍历用 `cc_dyn_core_seek`，不要用 `cc_dyn_core_get`（后者会把元素从数组中移除）。
- 释放顺序：逐元素释放 `key` / `value`，再用 `ccalloc(defines.array, 0, NULL)` 释放数组本体。
