# CCMake 命令行参数

CCMake 的命令行参数遵循 GNU/POSIX 风格，同时支持短格式和长格式。

## 基本格式

```text
ccmake [选项...]
```

示例：
```bash
ccmake -c project.ccm -f build.cmk -j 8
ccmake --config ../config.ccm --file make.cmk --verbose
ccmake -C ./build -D project=MyApp -t release
```

---

## 一、命令行参数列表

根据使用频率和重要性，参数分为三个层级。

| 短格式 | 长格式 | 类型 | 说明 |
|---|---|---|---|
| `-c <路径>` | `--config <路径>` | 配置 | 指定 `.ccm` 配置文件路径（必填） |
| `-f <路径>` | `--file <路径>` | 配置 | 指定 `.cmk` 构建脚本路径（必填） |
| `-C <目录>` | `--directory <目录>` | 配置 | 切换工作目录后再执行（参考 `make -C`） |
| `-j <N>` | `--jobs <N>` | 配置 | 并行任务数量。`0` 表示自动检测，默认值为 CPU 核心数 |
| `-D <键>=<值>` | `--define <键>=<值>` | 配置 | 在命令行追加/覆盖配置文件中的字段。一个 `-D` 后可跟多个键值对 |
| `-o <目录>` | `--output <目录>` | 配置 | 指定构建产物输出目录 |
| `-t <目标>` | `--target <目标>` | 配置 | 指定构建目标（如 `debug`、`release`） |
| `-v` | `--verbose` | 配置 | 详细输出模式，显示更多执行细节 |
| `-n` | `--dry-run` | 配置 | 只显示将执行的操作，不实际执行 |
| `-B` | `--always-build` | 配置 | 强制重新构建所有目标 |
| `-k` | `--keep-going` | 配置 | 遇到错误后继续构建不依赖失败项的目标 |
| `-h` | `--help` | ▲动作 | 输出帮助信息，执行后退出 |
| `-V` | `--version` | ▲动作 | 输出版本信息，执行后退出 |
| | `--list-targets` | ▲动作 | 列出可用构建目标，执行后退出（尚未实现） |
| | `--dump-config` | ▲动作 | 展开变量后输出完整配置，执行后退出（尚未实现） |

## 二、命令行传参规范

### 2.1 参数分类

| 类型 | 识别方式 | 示例 |
|---|---|---|
| **标志型** | 以 `-` 开头，不跟值 | `-v`, `--verbose`, `--help` |
| **键值型** | 以 `-` 开头，后跟值 | `-c x.ccm`, `-j 8` |

> CCMake 不接受位置参数：不以 `-` 开头的参数（如 `ccmake release`）会报“不合规的参数”。

### 2.2 解析规则

1. 键值型参数缺少值时立即报错并退出。
2. 键值型参数的值是空字符串时立即报错并退出。
3. `-D` 的每个键值对必须形如 `<键>=<值>`：缺少 `=`、键为空、值为空都报错并退出。一个 `-D` 会一直收集到下一个以 `-` 开头的参数为止。
4. 未知参数报错并退出。
5. 不支持紧凑写法（`-j8`）与等号写法（`--jobs=8`），值必须用空格分隔：`-j 8`、`--jobs 8`。

### 2.3 动作类参数与解析优先级

参数分为两类：

| 类型 | 说明 | 行为 |
|---|---|---|
| **配置类** | 收集构建所需的配置信息 | 解析到后写入 `ccmake_global_var`，继续解析后续参数 |
| **动作类** | 执行一个独立动作，不参与构建 | 解析到后执行动作，然后返回 `true`，不再解析后续参数 |

动作类参数分两种：

- **立即执行型**（`-h` / `-V`）：解析到即执行并返回 `true`，后续参数不再解析。
- **需要配置型**（`--list-targets` / `--dump-config`）：解析阶段只把请求记录到 `ccmake_global_var.action`，继续解析参数以收集 `.ccm` 等配置，由后续流程负责执行。

动作类参数的优先级规则（从高到低）：

```
1. 参数校验（错误检查）
     ↓ 无错误
2. 动作类参数执行
     → 执行后 return true，不继续
     ↓ 非动作类参数
3. 配置类参数收集 → 继续解析下一个
```

具体来说：

1. **错误 > 动作**：解析每个参数时，先检查值是否存在、格式是否合法。一旦发现错误，输出错误信息并返回 `false`，即使后面有动作类参数也不执行。例如 `ccmake -j -V` 会因 `-j` 缺值而报错，而非输出版本。
2. **动作 > 配置**：解析到一个合法的立即执行型动作类参数时，立即执行该动作并返回 `true`，不理会后面的参数。例如 `ccmake -V -c nonexist.ccm` 只输出版本信息，不会检查配置文件是否存在。需要配置型动作不做此短路，会继续收集参数。
3. **顺序解析**：参数按 `argv[1]` 到 `argv[argc-1]` 的顺序从前到后解析。如果同时存在多个立即执行型动作类参数，排在命令行最前面的优先生效。例如 `ccmake -h -V` 输出帮助信息，`ccmake -V -h` 输出版本信息。多个需要配置型动作同时出现时，以最后一个为准（写入 `action` 字段）。
4. **参数覆盖**：如果相同的参数重复出现，后出现的会覆盖之前的，以最后一次取值为准。`-D` 的键值对同样如此：重复的键以后出现者为准。

立即执行型动作执行后，`parse_cmd` 返回 `true`，`main` 走动作分支 `return 0` 退出；需要配置型动作只记录请求，由后续流程处理。

动作类参数列表：

| 参数 | 动作内容 |
|---|---|
| `-h` / `--help` | 打印帮助信息到 stdout，返回 `true` |
| `-V` / `--version` | 打印版本号到 stdout，返回 `true` |
| `--list-targets` | 记录动作请求，由后续流程从配置文件解析所有构建目标并列出（执行阶段尚未实现） |
| `--dump-config` | 记录动作请求，由后续流程展开所有变量后输出完整配置（执行阶段尚未实现） |

> `--list-targets` 与 `--dump-config` 的解析没有问题：解析阶段只记录请求、继续收集参数，不校验构建必填项；动作的执行属于后续流程，当前尚未实现，会在后续流程中报错退出。

## 三、`--help` 输出格式

```text
-c, --config <文件>          指定 .ccm 配置文件（必填）
-f, --file <文件>            指定 .cmk 构建脚本（必填）
-C, --directory <目录>       切换工作目录
-j, --jobs <数量>            并行任务数（0 = 自动检测，默认: CPU 核心数）
-D, --define <键=值>...      覆盖配置文件字段（可跟多个键值对）
-o, --output <目录>          构建产物输出目录
-t, --target <目标>          构建目标（如 debug, release）
-v, --verbose                详细输出
-n, --dry-run                仅显示操作，不执行
-B, --always-build           强制重新构建
-k, --keep-going             遇到错误继续构建
    --list-targets           列出可用构建目标
    --dump-config            展开变量后输出完整配置
-h, --help                   显示此帮助信息
-V, --version                显示版本信息
```

---

## 四、`--version` 输出格式

```text
CCMake - Crystal Cluster Make：
<平台> <架构>
版本：v<主版本>.<次版本>.<构建号>
```

示例（Windows AMD64）：

```text
CCMake - Crystal Cluster Make：
Windows AMD64
版本：v0.0.1
```

平台与架构在编译期确定：平台取 `Windows` / `Linux` / `Android`，架构取 `AMD64` / `ARM64` / `X86` / `ARM`。
