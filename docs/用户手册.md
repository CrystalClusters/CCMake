# CCMake 命令行参数

CCMake 的命令行参数遵循 GNU/POSIX 风格，同时支持短格式和长格式。

## 基本格式

```
ccmake [选项...] [目标...]
```

示例：
```bash
ccmake -c project.ccm -f build.cmk -j8 release
ccmake --config=../config.ccm --file=make.cmk --verbose
ccmake -C ./build -D project=MyApp -t release
```

---

## 一、命令行参数列表

根据使用频率和重要性，参数分为三个层级。

| 短格式 | 长格式 | 类型 | 说明 |
|---|---|---|---|
| `-c <路径>` | `--config <路径>` | 配置 | 指定 `.ccm` 配置文件路径 |
| `-f <路径>` | `--file <路径>` | 配置 | 指定 `.cmk` 构建脚本路径 |
| `-C <目录>` | `--directory <目录>` | 配置 | 切换工作目录后再执行（参考 `make -C`） |
| `-j <N>` | `--jobs <N>` | 配置 | 并行任务数量。默认值为 CPU 核心数 |
| `-D <键>=<值>` | `--define <键>=<值>` | 配置 | 在命令行追加配置文件中的字段 |
| `-o <目录>` | `--output <目录>` | 配置 | 指定构建产物输出目录 |
| `-t <目标>` | `--target <目标>` | 配置 | 指定构建目标（如 `debug`、`release`） |
| `-v` | `--verbose` | 配置 | 详细输出模式，显示更多执行细节 |
| `-n` | `--dry-run` | 配置 | 只显示将执行的操作，不实际执行 |
| `-B` | `--always-build` | 配置 | 强制重新构建所有目标 |
| `-k` | `--keep-going` | 配置 | 遇到错误后继续构建不依赖失败项的目标 |
| `-h` | `--help` | ▲动作 | 输出帮助信息，执行后退出 |
| `-V` | `--version` | ▲动作 | 输出版本信息，执行后退出 |
| | `--list-targets` | ▲动作 | 列出可用构建目标，执行后退出 |
| | `--dump-config` | ▲动作 | 展开变量后输出完整配置，执行后退出 |

## 二、命令行传参规范

### 2.1 选项风格

> 遵循 GNU 长选项规范，同时支持短格式和长格式。

**短格式**：单字母，前面一个 `-`
- 不带值的是标志型：`-v`、`-h`
- 带值的是键值型：`-c path.ccm`、`-j 8`

**长格式**：完整单词，前面两个 `--`
- 不带值：`--verbose`、`--help`
- 带值（空格分隔）：`--config path.ccm`、`--jobs 8`
- 带值（等号分隔）：`--config=path.ccm`、`--jobs=8`（**两种都支持**）

### 2.2 参数分类

| 类型 | 识别方式 | 示例 |
|---|---|---|
| **标志型** | 以 `-` 开头，不跟值 | `-v`, `--verbose`, `--help` |
| **键值型** | 以 `-` 开头，后跟值 | `-c x.ccm`, `--jobs=8` |
| **位置型** | 不以 `-` 开头 | `release`, `clean` |

### 2.3 解析规则

1. 遇到 `--` 时，后面的所有参数都视为位置参数（即使以 `-` 开头）。
2. 键值型参数缺少值时立即报错并退出。
3. 未知参数报错并退出，建议退出码为 `EINVAL`（22）。
4. 短格式支持合并写法：`-j8v` 等价于 `-j 8 -v`。

### 2.4 动作类参数与解析优先级

参数分为两类：

| 类型 | 说明 | 行为 |
|---|---|---|
| **配置类** | 收集构建所需的配置信息 | 解析到后写入 `ccmaker_global.cmd`，继续解析后续参数 |
| **动作类** | 执行一个独立动作，不参与构建 | 解析到后立即执行动作，然后返回 `true` 通知 `main` 正常退出，不再解析后续参数 |

动作类参数的优先级规则（从高到低）：

```
1. 参数校验（错误检查）
     ↓ 无错误
2. 动作类参数执行
     → 执行后 return true，不继续
     ↓ 非动作类参数
3. 配置类参数收集 → 继续解析下一个
```

具体来说：

1. **错误 > 动作**：解析每个参数时，先检查值是否存在、格式是否合法。一旦发现错误，当场 `fprintf(stderr, ...)` 并返回 `false`，即使后面有动作类参数也不执行。例如 `ccmake -V -j` 会因 `-j` 缺值而报错，而非输出版本。
2. **动作 > 配置**：解析到一个合法的动作类参数时，立即执行该动作并返回 `true`，不理会后面的参数。例如 `ccmake -V -c nonexist.ccm` 只输出版本信息，不会检查配置文件是否存在。
3. **顺序解析**：参数按 `argv[1]` 到 `argv[argc-1]` 的顺序从前到后解析。如果同时存在多个动作类参数，排在命令行最前面的优先生效。例如 `ccmake -h -V` 输出帮助信息，`ccmake -V -h` 输出版本信息。
4. **动作类参数不依赖配置类参数**：因为不需要，也不收集。例如 `-V` 输出版本号是编译时嵌入的常量，无需任何配置参数。

动作类参数执行后，`cc_parse_cmdline` 返回 `true`，`main` 走动作分支 `return 0` 退出。

动作类参数列表：

| 参数 | 动作内容 |
|---|---|
| `-h` / `--help` | 打印帮助信息到 stdout，返回 `true` |
| `-V` / `--version` | 打印版本号到 stdout，返回 `true` |
| `--list-targets` | 从配置文件解析所有构建目标并列出，返回 `true` |
| `--dump-config` | 展开所有变量后输出完整的解析后配置，返回 `true` |

## 三、`--help` 输出格式

参考 `gcc --help` 风格：

```
用法: ccmake [选项...] [目标...]

选项:
  -c, --config=<文件>        指定 .ccm 配置文件（必填）
  -f, --file=<文件>          指定 .cmk 构建脚本（必填）
  -C, --directory=<目录>     切换工作目录
  -j, --jobs=<N>             并行任务数（默认: CPU 核心数）
  -D, --define=<键>=<值>     覆盖配置文件字段
  -o, --output=<目录>        构建产物输出目录
  -t, --target=<目标>        构建目标（如 debug, release）
  -v, --verbose              详细输出
  -n, --dry-run              仅显示操作，不执行
  -B, --always-build         强制重新构建
  -k, --keep-going           遇到错误继续构建
      --list-targets         列出可用构建目标
      --dump-config          展开变量后输出完整配置
  -h, --help                 显示此帮助信息
  -V, --version              显示版本信息

示例:
  ccmake -c project.ccm -f build.cmk release
  ccmake --config project.ccm --file build.cmk -j8 -v
  ccmake -c config.ccm -f build.cmk -D source_dir=./custom_src
```
